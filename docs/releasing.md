# Releasing (#76)

Latest release: <https://github.com/jusso-dev/crosswire/releases/latest>

## Semver policy

- **MAJOR:** breaking config/env changes, destructive schema changes, or removed APIs/flags.
- **MINOR:** new features, additive migrations, new optional flags.
- **PATCH:** fixes with no config or schema change.

While `0.x`, minor bumps may include breaking changes; call them out under **Changed**.

## Cut a release

1. Move entries from `## [Unreleased]` in `CHANGELOG.md` into `## [X.Y.Z] - YYYY-MM-DD` and update the links. Merge to `main`.
2. Tag and push from `main`:
   ```sh
   git checkout main && git pull
   git tag -a vX.Y.Z -m "Crosswire vX.Y.Z" && git push origin vX.Y.Z
   ```
3. `.github/workflows/release.yml` runs CI, builds the image, generates the SBOM, runs the CVE gate,
   pushes `ghcr.io/<owner>/crosswire:vX.Y.Z` and `:sha-<sha>`, and creates the GitHub Release with
   the CHANGELOG section and `sbom.spdx.json` attached. It fails if the CHANGELOG has no section for the tag.
4. Promote to production: Actions → Deploy → `image_tag = vX.Y.Z`. The image tag matches the git tag.

Manual fallback: `gh release create vX.Y.Z --notes-file <notes> sbom.spdx.json`.

## Supply chain gate (#85)

- **SBOM:** SPDX JSON generated by Syft (`anchore/sbom-action`) for every CI image build (artifact)
  and every release (attached to the GitHub Release).
- **Scan:** Trivy on the runtime image. **CRITICAL** vulnerabilities with a fix available fail CI,
  the release, and the deploy build (production cannot be promoted from an image that failed).
- **Waivers:** add the CVE to `.trivyignore` with the reason, an ADR or issue link, and an expiry
  date. Waivers need a maintainer review. Triage: upgrade the base image (`node:24-bookworm-slim`)
  or the dependency first; waive only when the vulnerable code is unreachable.
